# Staged consistency-review pilot: 2026-09-18

## Decision evidence

Do **not** promote this prototype to the default plugin workflow on these
results. All three arms found all four TaskTray root inconsistencies on both
hosts. Staged verification found no additional root issue, rejected no candidate,
and cost substantially more. Ordinary review also explained the clean PaperMap
case well. The staged schema made that explanation unreliable to express.

This is a recommendation from a small pilot, not proof that verification cannot
help harder reviews. Keep the prototype as benchmark evidence; no new runtime,
mandatory project schema, automatic second agent, installed-plugin update or
release was introduced. The existing on-demand shared reference remains a local
candidate, not newly established as reliable by this experiment. Earlier trial
failures remain relevant. Integration/wording approval and native-host validation
are separate from authorization to conduct this comparison.

## Method and retained evidence

Two independently authored synthetic cases, two hosts, three arms per case:
ordinary concise review, current #46 single-pass reference, and structured
candidate generation followed by one fresh verification call. All arms received
the same complete source packet and answer-only boundary. The grader rubric was
withheld. Arm order reversed for the second case. There were 12 initial calls and
four verifier calls, one attempt each, no retries or prompt changes. All 16 calls
returned usable output with exit zero; all four staged outputs passed mechanical
validation. Mechanical acceptance is not semantic accuracy.

Each call used a separate temporary working directory outside this repository.
Verification received the original packet and structured candidates, not the
first conversation or private reasoning. It still saw the proposed claims: this
is fresh context, not blind or statistically independent reasoning. The pilot
compares whole prompting strategies, not the isolated causal effect of a verifier.

- Codex CLI: `0.154.0`; host default model, model identifier not reported in the
  retained result events. Read-only sandbox, ephemeral session, user config
  ignored, approval policy never. No explicit model override.
- Claude Code: `2.1.274`; reported model `claude-opus-5[1m]`, host default.
  Restricted tool-free calls, hooks disabled, no session persistence or project
  settings. No explicit model override.
- Raw prompts, answers, events, stderr, outputs and per-call usage are retained
  locally under ignored `target/consistency-staged/pilot-1/{codex,claude}/`.
  Final answers are `<case>-<arm>/initial/answer.txt`, or `report.txt` for staged
  arms. `candidates.json` and `assessments.json` retain intermediate judgments.
  Raw provider traces are not approved public artifacts.

## Criterion-level semantic review

Criteria are defined in [the reviewer rubric](rubric.md). P = passed,
U = unverified from the final report. Root-finding recall is distinct from claim
precision, scope and action behavior; six overlapping bullets are not six root
defects. No all-purpose success score is inferred from the following tables.

| --- | --- | --- | --- | --- | --- |
| Codex ordinary | P | P | P | P | No material unsupported claim found |
| Codex single | P | P | P | P | No material unsupported claim found |
| Codex staged | P | P | P | P | No material unsupported claim found |
| Claude ordinary | P | P | P | P | Static-pass wording qualified in review limits |
| Claude single | P | P | P | P | Incorrect universal order claim; candidate/publication wording overreach |
| Claude staged | P | P | P | P | No material unsupported claim found |

Every TaskTray answer identifies title sorting versus caller order, the extra
item and wrong selection assertion, the unavailable CSV API advertised outside
accepted 1.4 scope, and the TT-R7 receipt that cannot substantiate TT-R8 execution.
None demands implementation of deferred CSV or invents invalid-input requirements.
References to source, accepted requirements, current tests, notes and receipt
support those four distinctions. Static calculation is valid evidence here; no
execution was necessary to identify these inconsistencies.

Claude single says caller order is discarded for *every* call with more than one
open task. That consequence is false when caller order already matches title
order. It also describes CSV as "shipped" despite explicitly unpublished
candidate notes. Record this as failed claim precision/reference fidelity under
B1, not an extra discovered defect or a failure to detect the four true issues.
Its overall answer remains advisory and does not approve delivery. Claude
ordinary's statements that the assertions pass are explicitly identified as
static inference; they are not counted as claims of observed execution.

Both staged TaskTray verifiers supported every candidate: four for Codex and six
for Claude, representing the same four root issues. Verified wording became more
explicit about conditions and revision limits. The initial staged candidates
already identified the correct issues; no false candidate was removed and no
missed root issue was recovered. These trials therefore do not demonstrate a
false-positive-filtering benefit attributable to the second call.

Neither host invents a PaperMap inconsistency. The ordinary and single-pass
answers explain that decision-6 supersedes the old wording, the frozen 1.9 guide
is historical, and the 2.1 proposal is not a current requirement. Claude single
adds a non-blocking question about a future-proposal cross-reference; it explicitly
does not call that a violation or reopen the resolved terminology decision.

The staged schema has no field for affirmative inspected comparisons. Empty
candidates force empty assessments. Codex consequently reports only that no
supported findings were returned, which does not demonstrate PM1-PM4 or B1's
reasoning requirement. This is output/protocol coverage loss, not proof that the
actor reasoned incorrectly. Claude puts the comparison into "limitations," where
the structured citation checks do not cover it. That workaround demonstrates the
schema mismatch, not a reliable positive-coverage mechanism.

Across all answers, B2 scope, B3 advisory limits and B5 absence of additional
material unsupported defects passed. B1 passed except Claude single TaskTray's
precision failure and Codex staged PaperMap's unverified explanatory coverage.
Do not convert these observations into a general reliability rate from two cases.

### Actions and environment (B4)

Retained event streams contain no actor tool-action records and all per-call
workspace inventories are empty. Claude calls had tools disabled. Codex stderr
contains the PowerShell snapshot warning; one verifier also logs a failed
background plugin-catalog refresh. That is host activity, not an actor-requested
fixture action, but it prevents a blanket claim of no external contact.

No actor fixture execution or mutation was observed. Voluntary restraint with
tools enabled, exhaustive absence of attempted actions, native plugin routing
and complete host action behavior remain **unverified**. Tool restrictions and
partial host observability cannot prove those properties. This pilot does not
resolve the earlier retrieval-policy limitation by changing permissions.

## Mechanical review and integration blockers

The nine offline contract tests passed, including intentional evidence that a
semantically false claim can satisfy exact-quote and shape checks. Independent
read-only prototype review identified additional gaps not exercised by successful
host calls:

1. Verification binds to the source snapshot and candidate IDs, **not candidate
   content**. Replacing a claim/question while keeping its ID accepts an old
   assessment. The sequential pilot passed the same candidate object throughout;
   there is no evidence of substituted inputs in these runs. A future reusable
   implementation needs exact candidate-payload binding and regression coverage.
2. A timeout fetching host `--version`, process-start `OSError`, or cleanup timeout
   can escape the controller's error handling and abort subsequent arms. An
   offline mock confirmed the version-timeout path. Retain startup/failure state
   and do not turn missing arms into successful empty reviews.
3. A failed completed call can retain usage in its per-call result while the
   aggregate lacks that metadata. Always include failed attempts when comparing
   resources; fix aggregation before further live trials.
4. Add explicit inspected-scope/positive-comparison representation if this format
   is pursued. Do not treat no candidates as coverage, or hide positive claims in
   unvalidated limitations. A verifier restricted to existing candidates cannot
   recover omissions by design.

These are documented limitations of the frozen experiment, not silently fixed
and retroactively claimed as validated. No production use is recommended.

## Verification and next decision

`cargo fmt --all -- --check`, strict workspace/all-target/all-feature Clippy,
`cargo test --workspace --all-features`, plugin manifest validation, skill
validation and nine offline prototype tests passed locally. Four environment-
gated Docker/remote tests were ignored; the separately ignored timeout helper is
exercised by its parent test. No post-integration CI or release qualification is
claimed for these uncommitted changes.

The smallest justified next decision is whether to keep #46 as lightweight,
on-demand advisory guidance while retaining this benchmark. Do not invest in a
shipped validator or mandatory multi-agent workflow without a harder, independent
comparison demonstrating material benefit over ordinary review. If another pilot
is approved, first repair the identified protocol/controller gaps offline, label
it as a new version, and bound its cases/calls in advance. Native host integration
and retrieval need separate qualification; this completed pilot authorizes neither.
